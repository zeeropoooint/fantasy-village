## 1. 产品定位

一款**西幻皮的星露谷式 2D 生活模拟游戏**,主战场为手机(以应用形式安装),兼顾 PC 键盘调试。

核心特征(经需求澄清确认):

- **核心玩法**:种植经营 + 社交好感 + 休闲生活;**不含战斗**
- **小游戏**:生产型(钓鱼/采集等日常操作即小游戏)+ 事件型(节日/剧情触发),两者都要
- **时间结构**:完整昼夜 + 星期日历 + 四季轮转;NPC 按日程走位,作物按天生长,节日按日期触发
- **操作方式**:手机虚拟摇杆移动 + 靠近目标弹出交互按钮;PC 端 WASD 同构调试
- **美术规格**:MVP 用 16×16 像素风,**架构上与美术资源彻底解耦**,后续整体替换为手绘风格
- **联网**:弱联网,第一版仅账号+云存档、配置热更(无排行榜、无多人)

## 2. 总体架构

Godot 4.x + GDScript。全局能力全部走 **Autoload 单例 + 信号**(等价于全局状态管理 + 事件总线),不引入第三方游戏框架。

```
fantasy_village/
├── project.godot
├── autoload/           # 全局单例
│   ├── game_state.gd   # 玩家数据:金币、背包、好感度、当前日期、剧情标志
│   ├── time_manager.gd # 游戏时钟:时/分、星期、季节、年;时间变化发信号
│   ├── save_manager.gd # 存档序列化:本地 user:// + 云端同步(M5)
│   ├── scene_manager.gd# 场景切换与淡入淡出转场
│   ├── input_manager.gd# 虚拟摇杆/键盘统一抽象
│   └── audio_manager.gd# BGM/音效统一播放入口
├── scenes/
│   ├── world/          # 村庄、农场、室内场景
│   ├── player/         # 玩家角色
│   ├── ui/             # 摇杆、交互按钮、对话框、HUD
│   └── minigames/      # 每个小游戏一个独立场景
├── systems/
│   ├── interaction/    # 可交互约定与探测
│   ├── dialogue/       # 对话系统(JSON 驱动)
│   ├── minigame_host/  # 小游戏宿主(暂停世界→装载→结算)
│   ├── farming/        # 种植系统(M1)
│   └── schedule/       # NPC 日程(M2)
├── data/               # 作物、NPC、对话、日程的 .tres/.json 配置
└── assets/             # 像素图与音频(整层可替换为手绘)
```

世界场景节点组织:

1. **TileMapLayer**:地面装饰层 + 碰撞层(地面/墙壁/树木)
2. **YSort 容器**:玩家与 NPC 放入其中,按脚下 Y 坐标自动处理前后遮挡
3. **Camera2D**:跟随玩家,限制在地图边界内

关键原则:**客户端负责表现;涉及经济与防作弊的数值以后端为准**(M5 起,如离线收益按服务器时间结算)。

## 3. M0 切片范围:村庄漫步

一条完整的约 2 分钟体验,目标是打通全部核心技术管线,而非系统深度:

1. **起床出门**:室内场景 → 门口转场到村庄(验证场景切换管线)
2. **村庄漫步**:虚拟摇杆控制四方向行走,带动画;建筑/树木有碰撞
3. **遇到 NPC**:走近精灵药剂师,头上弹出交互按钮 → 点击 → 打字机对话框,3~5 句台词
4. **路边小游戏**:走到感叹号木牌触发「节奏点击」小游戏(约 30 秒,世界暂停)→ 结算页显示成绩 → 按成绩发放金币
5. **回家睡觉**:碰床 → 天数 +1、时钟重置 6:00 → 自动存档 → 第二天继续

M0 同时包含:金币/时间 HUD、键盘 WASD 调试支持、真机 APK 验证清单。

**明确不做(留给后续里程碑)**:种植、背包深度、多位 NPC、日程走位、季节、昼夜光影、联网。

## 4. 关键机制设计

### 4.1 交互系统

- 所有可交互物(NPC、门、床、牌子、以后的地块)统一约定:加入 `interactable` 组,提供 `interact()` 方法与 `prompt_text` 属性
- 玩家挂 Area2D 探测区,范围内始终只选中**最近的一个**目标并弹出交互按钮,避免多目标误触
- 交互按钮热区 ≥ 44×44 逻辑像素

### 4.2 对话系统(自研,不使用 Dialogic 插件)

- 台词为 JSON 数组(或 Godot Resource),字段支持:说话人、文本、立绘、选项、条件跳转
- 表现层:打字机逐字显示、点击/按键推进、支持选项分支
- 条件表达式支持基于好感度、日期、剧情标志的 `if` 分支
- 自研理由:未来与好感度、心事件、服务端配置热更深度耦合,格式 100% 可控;M5 台词可由后端下发热更新,无需重新发版

### 4.3 小游戏宿主

- `MiniGameHost` 为覆盖全屏的 CanvasLayer,`process_mode` 设为 `Always`
- 触发流程:暂停世界(`get_tree().paused = true`)→ 实例化小游戏场景 → 小游戏结束时发 `finished(score)` 信号 → 宿主恢复世界 → 将成绩交给触发来源对应系统结算
- 小游戏场景**只负责玩法与成绩**,不直接发放奖励
- 中途退出 = 无奖励
- M0 仅实现一个「节奏点击」小游戏,但宿主接口面向 M4 的钓鱼、采集 QTE、节日小游戏设计,即插即用

### 4.4 时间管理器(M0 只做最小版)

- 记录:`day`(天数)、`minute_of_day`;睡觉 → 天数 +1、时间重置 6:00
- 通过信号广播变化,HUD 与未来的光影/日程系统订阅
- 季节、星期、年等在 M2 扩展,数据结构预留

### 4.5 存档(M0 本地版)

- 序列化 GameState + TimeManager 状态为 JSON,写入 `user://save_slot_1.json`
- 存档带 `version` 字段,后续通过迁移函数链升级,不丢老档
- 睡觉自动存档;M5 增加云同步(版本号 + 冲突时本地/云端双份保留供玩家选择)

## 5. 美术解耦与手机适配

- 逻辑代码**不直接引用贴图路径**;角色外观、动画名、地块样式全部经 `data/` 配置资源间接引用,换手绘时仅替换 `assets/` 与配置
- 统一 16px 基准:角色锚点统一在脚底中心,碰撞框尺寸规范统一
- 显示拉伸:`stretch_mode = canvas_items`;UI 全部锚点自适应
- 摇杆左下、交互按钮右下;热区 ≥ 44px;预留刘海屏安全区
- M0 结束即导出 APK 真机验证(模拟器无法替代真机)
- 素材来源:Kenney.nl(CC0)、itch.io 免费像素包起步;工具用 Aseprite/LibreSprite

## 7. 测试与边界处理

- **GUT(GDScript Unit Test)**:时间推进、对话条件解析、小游戏成绩结算、存档序列化与版本迁移

- 边界约定:
  - 小游戏中途取消无奖励
  - 云存档冲突:本地/云端双份保留,玩家选择
  - 断网完全可玩;联网失败静默重试,不弹窗打扰
  - 所有存档带版本号与迁移函数链
